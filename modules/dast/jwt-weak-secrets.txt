# modules/dast/jwt-weak-secrets.txt - the BOUNDED, VENDORED weak-HMAC secret
# list for modules/dast/jwt.sh (docs/DESIGN.md §7.4, docs/STEP5-DAST-PLAN.md
# DAST-26, DAST-36 amendment).
#
# WHAT THIS IS.  A small, fixed, offline list of the HMAC signing secrets that a
# JWT library's own quick-start, a tutorial, or a copy-pasted example ships with
# and that reach production unchanged.  jwt.sh re-signs a captured token with
# each of these and reports the token as forgeable when a protected endpoint
# ACCEPTS the re-signed variant.  That is weak-key DETECTION, not key cracking:
# there is no permutation, no brute force, no rules engine, no incrementing
# counter.  The whole search space is the lines below.
#
# WHY IT IS BOUNDED AND WHY NO FLAG ENLARGES IT (DAST-36).
# docs/STEP5-DAST-PLAN.md's "What may be relaxed by the affirmation" table lists
# "credential brute forcing" as NEVER relaxable, and states in full: "DAST-26's
# weak-HMAC list ... is a bounded vendored file; the affirmation may raise the
# rate [it] runs at, never [its] size."  --i-own-target changes the request rate
# these attempts run at; it does not add a line here, and there is deliberately
# no --wordlist, no --jwt-secrets, and no environment variable that points at a
# larger file.  A tool that grew its guess list on a flag would be a cracking
# rig with a safety label, which is exactly what this file is not.  Enlarging
# the real search would be a design change to a frozen posture, argued in
# docs/FOUNDATION.md and docs/STEP5-DAST-PLAN.md, not a config knob.
#
# FORMAT.  One candidate secret per line.  A line whose first byte is `#` is a
# comment; a wholly empty line is ignored.  Every other line is used VERBATIM,
# bytes as written, with NO trimming and NO unescaping - a leading or trailing
# space in a secret is part of the secret, so this file must not carry
# incidental trailing whitespace.  The empty secret (HS256 signed with a
# zero-length key) is NOT listed here: it is its own check
# (DAST-JWT-EMPTY_HMAC-01), so that "the secret was literally empty" and "the
# secret was a common word" stay two distinct findings with two distinct
# remediations.
#
# The list is intentionally short.  A longer list is not a better check: these
# are the values that ship in framework examples and documentation, and a token
# signed with one of them is forgeable by anyone who has read that same public
# documentation.  Adding obscure entries trades that clarity for a slower pass
# and a weaker finding.
