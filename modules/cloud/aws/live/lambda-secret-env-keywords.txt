# modules/cloud/aws/live/lambda-secret-env-keywords.txt - the configurable
# input to CLOUD-LAMBDA-ENV_SECRET-01 (docs/DESIGN.md §8.6, docs/STEP6-CLOUD-PLAN.md
# CLOUD-21): which environment-variable KEY NAMES read as credential-shaped
# by that check.
#
# ONE ENTRY PER LINE. Whole-line `#` comments and blank lines are ignored.
# Point SCOURSH_CLOUD_LAMBDA_SECRET_ENV_KEYWORDS_FILE at another file to use a
# different list, or edit this one - it is data, never code, and nothing here
# is ever expanded, sourced or executed.
#
# THE MATCH IS A SUBSTRING ON A NORMALISED KEY, NOT A REGEX, ON PURPOSE - the
# identical convention and the identical reason modules/dast/sensitive-fields.txt
# states at length: a key is normalised by uppercasing it and deleting `_`
# and `-`, so `DB_PASSWORD`, `dbPassword` and `DB-PASSWORD` are one string,
# `DBPASSWORD`. A plain entry matches when it is a SUBSTRING of that; an entry
# prefixed with `=` must equal it exactly. Regexes were rejected for the same
# bash-`=~`-is-BSD-regcomp reason AGENTS.md's "Things measured on this
# codebase" records - a list written on one userland would quietly match
# differently on the other.
#
# USE `=` WHENEVER THE BARE WORD IS A COMMON INNOCENT PREFIX OR SUBSTRING.
# `=KEY` rather than `KEY` so `MONKEY_ISLAND_LEVEL` is not a credential;
# `=SECRET` is NOT needed here because `SECRET` alone is already narrow
# enough in practice, but a future addition should ask the same question
# `=admin`/`=pwd` answer in the DAST list.
#
# An empty list, or a file that cannot be read, is not an error: the check is
# then skipped with a recorded reason, exactly as a missing payload file
# degrades one DAST technique rather than failing the run.
#
# THIS IS A HINT LIST, AND A HIT IS NOT A PROOF. The check reports that an
# environment variable's NAME says it holds a credential; whether the VALUE
# genuinely is one is a judgement about the function, which is why confidence
# is `medium`. The value itself is inspected only for a small, unambiguous set
# of shapes (an AWS access key id, a PEM private-key header) that
# modules/cloud/aws/live/lambda_engine.sh matches directly rather than through
# this file - those are structural, not name-based, and belong in code the
# same way an ARN's partition segment does.
